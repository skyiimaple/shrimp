# Shrimp 前端 Agent 聊天设计

## 目标与范围

在现有 React 19 + Vite 应用的顶部栏增加 Agent 入口，打开可在任意页面使用的聊天弹窗。第一版只接 GLM 与 DeepSeek，浏览器直接请求模型 API，不增加 Spring Boot 聊天接口。每个浏览器站点仅有一份长期保存的对话历史；支持明确确认后清空。第一版仅允许 Agent 调用 JSON、Base64、时间戳、UUID、正则五项纯前端能力。不开放 HTTP 代理、任意 JavaScript、动态卡片或多会话。

## 交互

- 顶部栏按钮打开弹窗；桌面端使用右侧对话面板，窄屏使用全屏弹层。关闭不删除历史。
- 弹窗显示消息、工具调用与结果、输入框、发送/停止按钮、提供商和模型选择、Key 设置与删除、清空历史按钮。
- GLM/DeepSeek 共用一份历史。切换提供商后，后续轮次使用新模型；旧回复保留原提供商标记。
- Key 由用户填写并按提供商保存在 localStorage；不包含在导出内容或错误信息中。设置页明确说明同源脚本可读取浏览器本地 Key。
- 用户可看完整历史。每次只向模型发送有限的最近上下文，并提示较早消息不会持续传给模型。

## 数据与状态

- 使用 IndexedDB 保存单会话消息。记录类型包含 `user`、`assistant`、`tool`；消息有 ID、时间、内容、状态、提供商、可选工具元数据。消息按序追加，保留直到用户清空或浏览器数据被清理。IndexedDB 不可用时展示明确错误，不静默丢失历史。
- localStorage 保存两家 Key、所选提供商和模型。Key 不发送给 Shrimp 后端；浏览器仅向对应提供商固定 HTTPS 域名发起请求。
- 发送时截取最近 20 条可用于模型上下文的消息，并限制各条文本长度。工具结果也截断，避免请求无限增长。

## 模型连接

- 为 GLM 和 DeepSeek 提供固定端点与独立配置，统一使用它们支持的 Chat Completions 工具调用格式；各自的响应差异在适配层处理。
- 通过 `fetch` + ReadableStream 解析 SSE；适配层输出文本增量、完整工具调用、完成与错误事件。正确处理跨 chunk 的 UTF-8 和多段 SSE 帧、多个并行工具调用的增量参数。
- 必须先做真实浏览器连通性检查。没有用户 Key 时只能完成模拟响应自动化测试，不能声称生产 API 已连通。若某提供商 CORS 不允许浏览器直连，停止该提供商接入并报告，不自行加入服务端转发。
- AbortController 负责停止生成；取消后保留已收到文本并标记为中断。网络/API 错误要区别认证失败、速率限制、跨域/网络错误，且不回显 Key。

## 工具执行

- Agent 工具目录是固定白名单：`json_transform`、`base64_transform`、`timestamp_convert`、`uuid_generate`、`regex_match`。每项有 JSON Schema 和参数校验，执行函数复用现有 `web/src/tools/lib` 实现。
- 模型返回的是建议调用，不能绕过参数校验或调用未注册能力。单轮最多 3 次模型请求、最多 5 次工具调用。工具的输入和输出有大小上限。
- 正则在 Web Worker 中执行，主线程可在超时后终止 Worker；匹配结果数量也设上限，避免卡死页面。工具失败作为工具结果反馈给模型，同时展示给用户。
- HTTP 代理、文件系统、网络访问、动态代码执行均不出现在第一版工具目录。

## 安全与隐私

- 模型回复按纯文本展示，不作为 HTML 执行。用户内容和工具结果都不提升为系统指令。
- 不允许自定义 API Base URL；请求端点固定为官方域名。API Key 只在对应请求的 Authorization 头出现，不写入日志、URL、聊天记录或 IndexedDB。
- Key 保存于浏览器本地属于用户选择的便利性取舍，不保证抵御同源恶意脚本或浏览器扩展。清空历史与删除 Key 是独立操作。

## 验收

1. 任意页面可打开/关闭弹窗，刷新后历史保留；只有一份历史，无会话切换。
2. GLM/DeepSeek 可切换，Key 可分别保存和删除；无 Key 时不能发送并给出提示。
3. 流式文本、停止、错误、中断状态正常；解析器通过跨块 SSE 测试。
4. 五个工具的合法与非法参数有测试；未知工具被拒绝；正则灾难性模式可超时终止。
5. 清空历史需确认，清空后消息消失；Key 保留。
6. 前端测试、类型检查、lint、构建通过。真实 API 连通性另以用户 Key 在浏览器验证。
