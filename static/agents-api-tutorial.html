01 · Agents API 是什么？

它是一个通过 API 使用 OpenAI 托管的 Codex Agent 运行框架的方式。你的应用提交任务，框架负责模型与工具的循环调用、会话管理、上下文压缩、子任务编排和恢复。

先记住一句话：Agents API 提供 Agent 的运行与编排能力；Agent 仍需使用模型作出判断。创建会话时要在 agent.model 中选择模型，它不会“脱离模型”独立工作。

例如，你的应用可以让 Agent 调查一个问题：查资料、写代码验证、产生文件、汇报结果。用户稍后补充要求时，继续使用同一个会话即可。Agents API 于 2026 年 9 月 10 日进入公开测试阶段。

02 · 四个核心概念

01 / CONFIG

Agent

模型、行为指令、工具与 MCP 连接的配置。决定“由谁做、可以用什么”。

02 / COMPUTE

Environment

可选的执行环境。需要运行命令、读写文件时，选择托管或自有沙箱。

03 / STATE

Session

持久会话，保留配置、对话和工作状态。后续任务可以接续同一会话。

04 / PROGRESS

Events 与 items

事件报告正在发生什么；items 记录输入、工具活动及输出。应用通过事件流或 webhook 跟踪任务。

04 · 五分钟创建第一个会话

  1. 在 OpenAI Platform 项目创建应用 API Key，授予 api.agents.read、api.agents.write、api.responses.write 权限。
  2. 在你的开发机设置 OPENAI_API_KEY，不要把密钥放进 Agent 沙箱或浏览器页面。
  3. 选择 Python 或 JavaScript，安装对应 SDK，并运行下面的代码。
终端 · 准备环境（二选一安装） 
export OPENAI_API_KEY="你的 API Key"

# Python
python -m pip install --upgrade openai

# JavaScript / Node.js
npm install openai
Python · first_agent.py 
from openai import OpenAI

with OpenAI() as client:
    with client.beta.agents.sessions.create(
        agent={
            "model": "gpt-6-astra",
            "instructions": "先写代码，再运行验证，最后报告实际输出。",
        },
        environment={"type": "openai_hosted"},
        input="创建 tree.py，打印当前目录的文件树；运行它并展示结果。",
        stream=True,
    ) as events:
        for event in events:
            print(event.to_json(indent=None), flush=True)
JavaScript · first_agent.mjs 
import OpenAI from "openai";

const client = new OpenAI();
const events = await client.beta.agents.sessions.create({
  agent: {
    model: "gpt-6-astra",
    instructions: "先写代码，再运行验证，最后报告实际输出。",
  },
  environment: { type: "openai_hosted" },
  input: "创建 tree.py，打印当前目录的文件树；运行它并展示结果。",
  stream: true,
});

try {
  for await (const event of events) {
    console.log(JSON.stringify(event));
  }
} finally {
  events.controller.abort();
}

执行 python first_agent.py 或 node first_agent.mjs 后，你会看到流式事件。保存事件中的 session_id，它是继续该会话的标识，不能代替 API Key。官方示例使用 gpt-6-astra；实际开发时可以按支持情况选择适合的模型。若直接使用 cURL，请显式添加 OpenAI-Beta: agents=v1 请求头；SDK 会自动添加。

注意：这段示例会真正调用 API 并产生费用；本教程页面本身不会发送 API 请求，也不收集密钥。

05 · 理解会话、轮次和事件

一个 session 可以有多轮 turn。向空闲会话发消息会开始新一轮；在 Agent 正工作时发送消息则可以引导当前轮次。轮次是异步执行的，应用可以通过流式事件或 webhook 获知进展。

创建 session
→
提交任务
→
监听事件
→
检查结果并继续
  • agent.session.turn.completed 表示该轮结束，仍要检查工具执行结果。
  • turn.failed、turn.cancelled 或 session.failed 表示失败或取消；仅看到 agent.session.idle 不等于成功。
  • 事件流意外断开时，先查询已保存的会话与 items，再决定是否重试，以免重复执行任务。
  • 用完后先下载需要的文件，再删除不再使用的会话。

实际操作：向同一会话发送第二条任务

第一轮完成后，用保存的会话 ID 发送 agent.session.input.message。正式应用应先订阅事件流，再发送消息，避免错过开头的事件。下面的代码仅演示发送动作：

Python · 继续会话 
from openai import OpenAI

session_id = "替换为第一轮返回的 sess_..."
with OpenAI() as client:
    client.beta.agents.sessions.events.create(
        session_id,
        events=[{
            "type": "agent.session.input.message",
            "input": [{
                "role": "user",
                "content": [{
                    "type": "input_text",
                    "text": "给 tree.py 增加最大层级参数，运行并展示结果。",
                }],
            }],
        }],
    )
JavaScript · 继续会话 
import OpenAI from "openai";

const client = new OpenAI();
const sessionId = "替换为第一轮返回的 sess_...";

await client.beta.agents.sessions.events.create(sessionId, {
  events: [{
    type: "agent.session.input.message",
    input: [{
      role: "user",
      content: [{
        type: "input_text",
        text: "给 tree.py 增加最大层级参数，运行并展示结果。",
      }],
    }],
  }],
});

任务完成后，可在 Platform 控制台查看会话日志；在应用中则通过事件与已保存的 items 获取过程和输出。长期任务可用 webhook 接收状态变化。

06 · 环境和工具怎么选？

环境 适用情况 你需要知道
none 问答、搜索、远程 MCP 或函数工具 没有内建命令行和工作区文件。
openai_hosted 运行脚本、编辑文件、生成报告 OpenAI 创建 Linux 沙箱；可设置依赖、文件、容器大小与网络权限。
self_hosted 私有网络、专用软件、自有计算资源 你的服务负责环境的启动、连接、恢复与关闭。

工具可包括网页搜索、MCP 和应用自定义函数。远程 MCP 可由运行框架调用；函数工具则需要你的服务接收调用并返回结果。只开启任务真正需要的权限和网络访问。

自定义函数如何接入？

在 agent.tools 中声明名称、说明和参数 JSON Schema。Agent 需要调用时，会发出 agent.session.requires_action；你的服务读取 required_actions、运行函数，再把结果提交回会话。对有外部副作用的函数，应按 session、turn 和 call ID 保存结果，断线恢复时先核对。

托管沙箱的文件可在沙箱存活期间跨轮次使用；放在 /workspace/outputs 的文件会在轮次结束时发布为可下载产物。不要依赖临时工作区永久保存文件。

如何取回结果文件？

让 Agent 将文件写入 /workspace/outputs。该轮完成后，通过会话 Artifacts API 列出产物，再按 artifact ID 下载。自托管环境的文件从自己的存储取得；none 环境没有文件系统，应读取 session items。

08 · 常见问题

Agents API 是不是只有编排，不需要绑定模型？

不是。它提供编排与会话能力，但 Agent 仍需模型作出决策。创建会话时使用 agent.model 指定模型；你不必永远绑定某一个固定型号。GLM、DeepSeek 的第三方模型接入见下一节。

它和 Codex App 是同一个东西吗？

它们都使用 Codex Agent 能力，但 Agents API 是供你自己的应用调用的开发接口。你需要实现自己的用户界面、业务流程和所需的工具处理。

用户关掉网页，任务会停止吗？

关闭事件流不会自动取消任务。应用应保存 session_id，之后查询会话状态与结果；长期任务可通过 webhook 获取状态变化。

一定要有沙箱吗？

不需要。纯问答或远程工具工作可设置 environment.type 为 none；要运行命令或处理工作区文件时，再选择沙箱。

09 · 如果要用 GLM 或 DeepSeek

关键边界：下方代码使用的是 OpenAI Agents SDK，并非前文的托管 Agents API。当前 Agents API 文档没有提供将第三方模型的 base_url 和密钥交给托管会话、由其调用 GLM 或 DeepSeek 的方式。不能只把 agent.model 改成 glm-5.3 或 deepseek-flash，就期待前面的会话示例工作。

Agents SDK 在你的应用进程中运行 Agent 循环，可配置第三方 OpenAI 兼容端点。以下是二选一的配置示例：GLM 使用智谱开放平台的 glm-5.3；DeepSeek 使用官方示例中的 deepseek-flash。模型名称和端点会变化，上线前请核对提供商文档。

Python · external_agent.py 
import asyncio
import os
from agents import Agent, Runner, AsyncOpenAI, OpenAIChatCompletionsModel, set_tracing_disabled

PROVIDERS = {
    "glm": ("ZAI_API_KEY", "https://open.bigmodel.cn/api/paas/v4/", "glm-5.3"),
    "deepseek": ("DEEPSEEK_API_KEY", "https://api.deepseek.com", "deepseek-flash"),
}

async def main():
    provider = os.environ.get("MODEL_PROVIDER", "glm")
    key_name, base_url, model_name = PROVIDERS[provider]
    set_tracing_disabled(True)  # 没有 OpenAI Platform Key 时关闭 OpenAI 追踪上报
    model = OpenAIChatCompletionsModel(
        model=model_name,
        openai_client=AsyncOpenAI(api_key=os.environ[key_name], base_url=base_url),
    )
    agent = Agent(name="研究助手", instructions="用中文简洁回答。", model=model)
    result = await Runner.run(agent, "解释 Agent 编排和模型推理的分工。")
    print(result.final_output)

if __name__ == "__main__":
    asyncio.run(main())

JavaScript · external_agent.mjs 
import { Agent, Runner, OpenAIProvider, setTracingDisabled } from "@openai/agents";

const providers = {
  glm: {
    key: process.env.ZAI_API_KEY,
    baseURL: "https://open.bigmodel.cn/api/paas/v4/",
    model: "glm-5.3",
  },
  deepseek: {
    key: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com",
    model: "deepseek-flash",
  },
};

const selected = providers[process.env.MODEL_PROVIDER ?? "glm"];
if (!selected?.key) throw new Error("请设置 MODEL_PROVIDER 和对应的 API Key");

setTracingDisabled(true); // 没有 OpenAI Platform Key 时关闭 OpenAI 追踪上报
const modelProvider = new OpenAIProvider({
  apiKey: selected.key,
  baseURL: selected.baseURL,
  useResponses: false, // 第三方兼容端点走 Chat Completions
});
const agent = new Agent({
  name: "研究助手",
  instructions: "用中文简洁回答。",
  model: selected.model,
});
const runner = new Runner({ modelProvider });
const result = await runner.run(agent, "解释 Agent 编排和模型推理的分工。");
console.log(result.finalOutput);

运行 python external_agent.py 或 node external_agent.mjs。两段代码使用提供商自己的 API Key 和计费，不创建 Agents API 的 session_id，也不自动获得其托管沙箱、持久会话或恢复机制。第三方端点的工具调用、结构化输出等兼容程度需要按具体模型验证。

10 · 推荐学习路线

  1. 先运行本页的最小示例，观察事件流与 session_id。
  2. 再用同一会话发送后续任务，理解状态如何保留。
  3. 加入一个工具，例如网页搜索或自己的函数工具。
  4. 测试事件流断开、工具失败与会话清理。
  5. 最后再按需要加入文件输入、沙箱配置和子 Agent。
