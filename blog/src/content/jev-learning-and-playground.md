Jev 是 TypeSafe 提供的模型。它接收待判断的材料和带类型的问题，返回结构化答案，适合分类、评分和判断某个陈述是否成立。[官方介绍](https://docs.typesafe.ai/introduction)

例如，一条客服消息可以同时用于判断是否紧急、应该分配给哪个团队，以及客户的情绪程度。

## 三种问题类型

| 类型   | 用途                 | 返回内容                 |
| ------ | -------------------- | ------------------------ |
| Noul   | 判断一个陈述是否成立 | `noul`，0 到 1 的概率值  |
| Choice | 从给定选项中选择     | 选项、各选项概率和置信度 |
| Score  | 按有序标准评估       | 分值、概率和置信度       |

Noul 适合“消息是否紧急”这样的判断。Choice 适合团队分配或内容分类。Score 适合按明确的等级描述评估程度，例如“平静陈述事实”“有些不满”“非常愤怒”。[类型说明](https://docs.typesafe.ai/introduction)

## 使用 Jev 调用试炼场

打开 [Jev 调用试炼场](https://shrimp-web-self.vercel.app/tools/jev)，即可编辑输入材料和问题。

下方编辑界面截图来自线上页面，使用占位 Key 展示；结果截图由使用者提供，展示一次调用的返回内容。

### 1. 输入 API Key

首次打开时填写自己的 TypeSafe API Key，保存后进入编辑界面。后续可以更换或清除 Key。

![线上 Jev 试炼场首次填写 API Key 的界面](/images/jev/start.png)

Key 会以明文保存在当前浏览器的 `localStorage` 中。提交请求时，Key、输入材料和问题会经同源转发接口发送到 TypeSafe；请求预览不包含 Key。

### 2. 填写 state

`state` 是希望模型判断的材料，支持文本和 JSON 两种输入方式。

试炼场默认提供了一条消息：

> 客户说：支付集成已连续三天失败，请尽快协助。

可以直接使用这条示例，也可以换成自己的内容。选择 JSON 模式时，需要输入合法的文本字符串、对象或数组。

### 3. 添加问题

点击“添加 Noul 问题”“添加 Choice 问题”或“添加 Score 问题”，填写问题 ID 和判断说明。

以客服消息为例，可以添加三个问题：

- **紧迫性**：选择 Noul，填写“这条消息是否表达了紧迫性？”
- **处理团队**：选择 Choice，添加付款、技术和销售三个选项，并写出每个选项的含义。
- **情绪程度**：选择 Score，添加从“平静陈述事实”到“非常愤怒”的等级描述。

![线上试炼场的 Noul、Choice 和 Score 问题编辑界面](/images/jev/editor.png)

一个请求可以包含多个问题。问题 ID 用来在结果中识别对应答案，选项描述和等级说明则用于明确判断标准。

### 4. 预览请求

点击“展开请求 JSON 预览”，检查实际提交的内容。也可以切换到“高级：编辑 JSON”，直接编辑问题结构。

下面是一份完整示例，可以把其中的 `questions` 内容用于高级编辑：

```json
{
  "model": "jev-latest",
  "state": "客户说：支付集成已连续三天失败，请尽快协助。",
  "questions": {
    "urgent": {
      "type": "noul",
      "instructions": "这条消息是否表达了紧迫性？"
    },
    "department": {
      "type": "choice",
      "instructions": "应该由哪个团队处理？",
      "criteria": {
        "billing": "付款或订阅问题",
        "technical": "技术故障或集成问题",
        "sales": "销售咨询"
      }
    },
    "frustration": {
      "type": "score",
      "instructions": "客户的挫败程度如何？",
      "criteria": ["平静陈述事实", "有些不满", "非常愤怒"]
    }
  }
}
```

![展开请求 JSON 后的预览界面](/images/jev/request-preview.png)

如果 JSON 包含表单无法表达的内容，页面会提示继续使用高级模式。输入不合法或问题结构不完整时，先根据提示修正，再提交。

### 5. 提交并查看结果

提交成功后，结果按问题 ID 分别展示：

- Noul 显示判断成立的概率。
- Choice 显示选中的选项，并在响应提供时显示概率和置信度。
- Score 显示分值，并在响应提供时显示概率和置信度。

页面还会显示输入、输出 token 用量，以及原始响应 JSON，方便检查完整结果。

下面是一次调用的结果截图：

![Jev 调用结果：紧迫性概率、团队分类和情绪评分](/images/jev/result.png)

图中模型为 `jev-1.13.0`，输入用量为 435 tokens，输出为 72 tokens：

- **Noul**：`urgent` 返回 96%，表示模型对“消息表达了紧迫性”这一判断给出的概率。
- **Choice**：`choice_1` 选择 `technical`，置信度为 97%；技术选项的概率显示为 98%，付款为 2%，销售为 0%。选项概率与置信度是分别展示的字段。
- **Score**：`score_1` 返回 0.96，置信度为 94%；等级概率显示“平静陈述事实”4%、“有些不满”96%、“非常愤怒”0%。0.96 是分值，不是 96% 的置信度。

这些数值对应截图中的一次调用，其他输入或问题设置可能得到不同结果。

访问入口：[打开 Jev 调用试炼场](https://shrimp-web-self.vercel.app/tools/jev)。

### 常见错误

| 提示               | 可以检查什么                   |
| ------------------ | ------------------------------ |
| API Key 无效       | Key 是否填写正确，是否仍然有效 |
| 请求内容未通过校验 | 问题类型、说明、选项和等级结构 |
| 请求过于频繁       | 稍后再试                       |
| 服务暂时繁忙       | 稍后重试                       |
| 无法连接服务       | 网络和同源转发接口是否可用     |

## Jev 的接入经历

Jev 试炼场先加入工具箱，随后补上 API 转发和 Vercel 部署支持，再优化请求与响应处理。

接入中需要处理的是本地开发和线上部署的调用差异。现在浏览器统一请求 `/api/jev/evaluate`：本地由 Vite 转发，部署到 Vercel 后由 Function 转发至 TypeSafe，因此不需要为两种环境分别修改前端调用地址。

Jev 调用不依赖工具箱中用于 HTTP 请求的 Java 服务。若把页面部署到其他纯静态环境，还需要提供对应的同源转发接口。

接入时也补充了无效 Key、请求校验失败、限流和服务繁忙等错误提示，并保留原始响应与用量展示，便于在页面中确认调用情况。
